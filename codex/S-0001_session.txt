### Restricciones de Meta y viabilidad

Meta describe el *scraping* como recopilación automatizada desde sitios web u otras interfaces creadas para las personas, y su material público indica que obtener datos mediante automatización sin permiso puede infringir sus términos. Por ello, leer automáticamente el DOM **sigue siendo una actividad que requiere revisión**, aunque no se envíen mensajes ni se cambie la conversación. La autorización del usuario para desarrollar el programa no equivale a permiso de Meta. [Centro de ayuda de Meta: recopilación de datos](https://www.facebook.com/help/463983701520800), [Meta: cómo combate el scraping](https://about.fb.com/news/2021/04/how-we-combat-scraping/)

La documentación oficial consultada de Messenger describe conversaciones de una página de Facebook o una cuenta profesional de Instagram y exige permisos, tokens de página y, para ciertos accesos, acceso avanzado. La documentación de envío también establece requisitos de permisos y una ventana estándar de respuesta de 24 horas. **No encontré documentación que confirme que esas interfaces admitan las conversaciones de compradores vinculadas a publicaciones de Marketplace**, especialmente para un vendedor que opera desde un perfil personal. Eso debe quedar sin resolver hasta verificarlo con Meta. [API de conversaciones](https://www.postman.com/meta/messenger-platform-api/folder/22794852-255610cd-47f5-4f4d-b3fa-71aec360be9a), [Send API](https://www.postman.com/meta/messenger-platform-api/folder/vilwbh4/send-api)

No pude leer los términos legales completos en la consulta directa: la página redirigió a inicio de sesión/bloqueo temporal. La conclusión de política se limita a los materiales públicos citados; la autorización concreta aplicable al caso sigue pendiente.

## 3. Recomendación de navegador y stack

Recomiendo **Python 3.13.7 + Playwright para Python + Chromium administrado por Playwright**, inicialmente en modo visible y con un perfil de prueba separado. Python 3.13 está instalado, y la documentación de Playwright muestra esa versión en sus ejemplos de CI. Playwright y los navegadores necesarios no están instalados; Playwright requiere descargar los binarios y estos pueden ocupar cientos de megabytes. [CI de Playwright](https://playwright.dev/python/docs/ci), [descarga de navegadores](https://playwright.dev/python/docs/browsers)

Para la base de datos, recomiendo **SQLite mediante `sqlite3`**, ya disponible en ambas versiones de Python. No necesita un servidor aparte y guarda la base en un archivo local. Python y Playwright son software sin coste de licencia según sus fuentes oficiales; Playwright publica licencia Apache 2.0 y SQLite está en dominio público. [Python](https://www.python.org/about/), [Playwright Python](https://github.com/microsoft/playwright-python/blob/main/pyproject.toml), [SQLite](https://www.sqlite.org/copyright.html)

La elección favorece reproducibilidad y separación del perfil personal. Como limitaciones, Chromium administrado por Playwright no es la distribución Chrome y la sesión de un perfil persistente queda guardada localmente en ese perfil. Si se requiere contrastar la interfaz con Chrome, el Chrome instalado puede ser un segundo navegador usando otro directorio de datos; nunca se debe reutilizar el perfil personal. La estabilidad prolongada y los selectores de Marketplace no se pueden evaluar sin una inspección autorizada de su interfaz.
